optimize-image-folder

写真フォルダを見張って、追加された写真を画質の劣化なしで JPEG XL に変換するツール。JPEG は元の JPEG にバイト単位で戻せる形で約 20% 小さく、PNG は完全ロスレスで 30〜45% 小さくなります。何もしていない間はリソースを使いません。

インストール

Homebrew (おすすめ)

brew install tsubasatommy/tap/optimize-image-folder
optimize-image-folder install

install で、変換するフォルダ (既定は ~/Pictures。写真ライブラリの中身は対象外)、元ファイルの扱い、既存の写真も変換するかを聞かれます。設定画面は optimize-image-folder settings か ~/Applications/Optimize Image Folder.app で開けます。

Homebrew を使わない場合

curl -fsSL https://tsubasatommy.github.io/optimize-image-folder/install.sh | sh

最新リリースをダウンロードし、SHA256 を確認してから ~/.local/bin に置きます。macOS 14 以降なら、変換した JPEG XL を Finder・プレビュー・写真でそのまま表示できます。

winget (おすすめ)

winget install TsubasaTommy.OptimizeImageFolder

インストーラーを直接ダウンロードする場合

Windows x64 / ARM64 共通・管理者権限不要 ⬇ Setup.exe

インストール中に、元ファイルの扱いと既存の写真も変換するかを選びます。設定画面はスタートメニューの「Optimize Image Folder」から開けます。

PowerShell から入れる場合

irm https://tsubasatommy.github.io/optimize-image-folder/install.ps1 | iex

最新の Setup.exe をダウンロードし、SHA256 を確認してから起動します。

インストーラーにはコード署名をしていません (証明書は有料のため)。winget で入れると SmartScreen の警告は出ません。ブラウザでダウンロードした Setup.exe では警告が出ることがあるので、SHA256SUMS.txt でハッシュを確かめてから「詳細情報」→「実行」を選んでください。

JPEG XL を表示するには

OS表示方法
macOS 14 以降標準で表示できます (Finder、プレビュー、写真)。
Windows 11 24H2 以降Microsoft 公式の無料拡張「JPEG XL Image Extension」で、エクスプローラーやフォトで表示できます。インストーラーがこの拡張も一緒にインストールします (チェックを外せば入れません)。あとから入れる場合は、設定画面の「拡張機能をインストール」を押すか、次を実行します。
winget install --id 9MZPRTH5C0TB --source msstore
それ以前の OS変換は行われますが、標準のアプリでは表示できません。restore でいつでも元に戻せます。

変換の仕様

元の形式変換方法元ファイルを消す前の検証
JPEGJPEG のロスレス再圧縮 (EXIF・XMP・ICC も保持)JPEG XL から復元した JPEG が元ファイルとバイト単位で一致すること
PNG / TIFF / BMP / ロスレス WebP完全ロスレス。色空間・16 bit・透過・向き・EXIF / XMP を保持デコードした画素が元と完全に一致すること
HEIC / 非可逆 WebP / RAW など変換しません (劣化なしで変換できないため、元のまま残します)
元の写真は既定で削除されます。 上の検証に成功し、元ファイルが変換中に変わっていないことを確かめてから削除します。心配な場合は、インストール時に「ゴミ箱へ移動」か「残す」を選んでください。削除したあとでも optimize-image-folder restore <ファイルまたはフォルダ> で元に戻せます (JPEG はバイト単位で元どおり、それ以外は同じ画素の PNG)。

4K 写真での実測値 (Apple Silicon)

元のファイルJPEG XL時間
JPEG 2.29 MB1.85 MB (-19%)1.9 秒
PNG 10.3 MB (圧縮の強さ 3)6.87 MB (-33%)6.6 秒
PNG 10.3 MB (圧縮の強さ 7、既定)5.76 MB (-44%)28 秒

変換は低優先度の子プロセスで行うので、時間がかかっても作業の邪魔になりません。「圧縮の強さ」で変わるのはサイズと時間だけで、画質は常に元と同じです。

特徴

待機中はリソースを使わない

macOS では、フォルダが変わったときだけ launchd がプロセスを起動し、終われば終了します。Windows では、1 本のスレッドが I/O 完了ポートで眠るだけです。

設定画面

圧縮の強さ、変換するフォルダ、除外するフォルダを設定できます。開いている間だけ動く別プロセスなので、常駐はしません。

OS のネイティブ API

Rust から FSEvents・launchd・ImageIO・AppKit (macOS)、ReadDirectoryChangesW・IOCP・WIC・Win32 (Windows) を直接呼び出します。

変換は使い捨てプロセスで

必要なときだけ低優先度 (Background QoS / EcoQoS) の子プロセスを起動し、終わったら終了します。メモリはすべて OS に返されます。

安全な置き換え

検証 → 一時ファイルに書いて fsync → rename → 元ファイルが変わっていないか確認、の順に進め、日時や Finder タグも引き継ぎます。

公式の JPEG XL 実装

エンコードは libjxl 0.13、検証は jxl-rs (どちらも libjxl プロジェクト、BSD-3-Clause) を使います。

使い方

コマンド内容
install設定を作り、自動起動に登録します (--folder --exclude --new-only --scan-existing --original delete|trash|keep --effort 1-9 --yes)
settings設定画面を開きます
status状態、設定、監視フォルダにアクセスできるか、最近のログを表示します
convert <パス>ファイルやフォルダを今すぐ変換します (--dry-run で確認だけ)
restore <パス>JPEG XL から元のファイルを復元します (--delete-jxl で .jxl を削除)
start / stop / restart監視の開始・停止・再起動

Windows ではインストーラーがコマンドを PATH に追加します (%LOCALAPPDATA%\Programs\OptimizeImageFolder)。新しいターミナルから使えます。

アンインストール

macOS:

optimize-image-folder uninstall --purge
brew uninstall optimize-image-folder

Windows: 「設定」→「アプリ」から「Optimize Image Folder」をアンインストールするか、次を実行します。

winget uninstall TsubasaTommy.OptimizeImageFolder

変換済みの JPEG XL はそのまま残ります。元に戻したい場合は、アンインストールの前に restore を実行してください。
