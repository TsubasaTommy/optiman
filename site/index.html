写真はそのまま。
容量だけ、小さく。

写真フォルダに追加された写真を、画質を一切変えずに JPEG XL へ変換します。JPEG は元のファイルにいつでも戻せる形のまま約 2 割、PNG は約 3〜5 割小さくなります。待っている間は CPU を使いません。

macOS 11 以降 (Homebrew)

brew install tsubasatommy/tap/optiman
optiman install

Windows 10 / 11 (x64 と ARM64 の両方に対応、管理者権限は不要)

Setup.exe をダウンロード

SmartScreen の警告が出た場合は、インストールの説明を見てください。

どれだけ小さくなるか

写真の PNG 10.6 MB は、劣化なしで 6.2 MB に。画質「高」なら 840 KB まで小さくなります。

実際の画像 4 枚を Optiman で変換して、サイズを測りました。画質は 4 段階から選べます。既定の「最高」は劣化なしで、画質はそのまま、容量だけが減ります。もっと減らしたいときは、設定で「高」「中」「低」を選びます。

棒は元のサイズに対する大きさです。※ 非可逆にしても劣化なしより 1 割以上小さくならない画像は、劣化なしで保存します。画像は macOS 付属の壁紙 (航空写真と Sonoma) と Web ページのスクリーンショットで、Apple Silicon の Mac で測りました。変換にかかった時間は 1 枚あたり 1〜5 秒です。

最高 (劣化なし) と、高・中・低の違い

項目最高 (劣化なし、既定)高・中・低 (非可逆)
画質元とまったく同じ「高」なら見た目ではほぼ区別できない。「中」「低」は拡大すると分かることがある
大きさ写真の PNG で約 6 割に写真の PNG で「高」は約 13 分の 1、「低」は約 27 分の 1 に
元に戻すいつでも完全に戻せる戻せない。圧縮したあとの画質のまま
JPEG元のファイルに戻せる形で約 2 割減る同じ。JPEG はどの画質でも劣化なし
向いているもの大事な写真、あとで編集する画像見返すだけの画像、容量を大きく空けたいとき

最高 (劣化なし) なら、元の画像にそのまま戻せます

上の 4 枚を「最高」で変換してから optiman restore で戻し、元の画像と比べました。JPEG は元のファイルとバイト単位で同じに戻り、PNG の 3 枚は合計 2,822 万画素がひとつ残らず元と同じでした。TIFF、BMP、WebP も、同じ画素の PNG として戻せます。

インストール

Homebrew (おすすめ)

brew install tsubasatommy/tap/optiman
optiman install

install で、変換するフォルダ (既定は ~/Pictures。写真ライブラリの中身は対象外)、元ファイルの扱い、既存の写真も変換するかを聞かれます。設定画面は optiman settings か ~/Applications/Optiman.app で開けます。

Homebrew を使わない場合

curl -fsSL https://tsubasatommy.github.io/optiman/install.sh | sh

最新リリースをダウンロードし、SHA256 を確かめてから ~/.local/bin に置きます。

インストーラー

Setup.exe をダウンロード

x64 と ARM64 の両方に対応し、管理者権限は要りません。インストール中に、元ファイルの扱いと既存の写真も変換するかを選びます。設定画面はスタートメニューの「Optiman」から開けます。

インストーラーにはコード署名をしていません (証明書が有料のため)。ブラウザでダウンロードすると SmartScreen の警告が出ることがあります。その場合は SHA256SUMS.txt でハッシュを確かめてから、「詳細情報」を押して「実行」を選んでください。下の PowerShell や winget で入れると警告は出ません。

PowerShell から入れる場合

irm https://tsubasatommy.github.io/optiman/install.ps1 | iex

最新の Setup.exe をダウンロードし、SHA256 を確かめてから起動します。

winget

winget install TsubasaTommy.Optiman

winget への登録は Microsoft の審査中です (winget-pkgs #486317)。見つからない場合は、上のインストーラーか PowerShell で入れてください。

Windows ではインストーラーがコマンドを PATH に追加します (%LOCALAPPDATA%\Programs\Optiman)。新しいターミナルから使えます。

JPEG XL を表示するには

OS表示のしかた
macOS 14 以降そのまま表示できます (Finder、プレビュー、写真)。
Windows 11 24H2 以降Microsoft 公式の無料拡張「JPEG XL Image Extension」を入れると、エクスプローラーやフォトで表示できます。インストーラーがこの拡張も一緒に入れます (チェックを外せば入れません。winget で入れた場合は入らないので、下の方法で入れてください)。
それ以前の OS変換はされますが、標準のアプリでは表示できません。restore でいつでも元に戻せます。

拡張をあとから入れる場合は、設定画面の「拡張機能をインストール」を押すか、次を実行します。

winget install --id 9MZPRTH5C0TB --source msstore

変換の仕様

元の形式変換のしかた元ファイルを消す前の確認
JPEGJPEG のロスレス再圧縮。EXIF、XMP、ICC も保持JPEG XL から復元した JPEG が、元ファイルとバイト単位で一致すること
PNG、TIFF、BMP、ロスレス WebP完全ロスレス。色空間、16 bit、透過、向き、EXIF / XMP を保持デコードした画素が、元と完全に一致すること
PNG など (画質を高・中・低にしたとき)非可逆の JPEG XL。透過、向き、EXIF / XMP は保持デコードでき、元の画像と大きく違わないこと
HEIC、非可逆 WebP、RAW など変換しません。劣化なしでは変換できないため、元のまま残します

元の写真は、既定では削除されます。上の確認に成功し、変換中に元ファイルが変わっていないことを確かめてから削除します。心配な場合は、インストール時に「ゴミ箱へ移動」か「残す」を選んでください。削除したあとでも optiman restore <ファイルまたはフォルダ> で元に戻せます (JPEG はバイト単位で元どおり、それ以外は同じ画素の PNG)。

「圧縮の強さ」で変わるのはサイズと時間だけで、画質は変わりません。変換は低優先度の子プロセスで行うので、時間がかかっても作業の邪魔になりません。

待っている間と変換中

待機中の実測値CPU 時間スレッド専有メモリ
macOSプロセス自体がありません
Windows x6430 秒間で 0 ms1 本2.3 MB
Windows ARM6430 秒間で 0 ms2 本2.8 MB
待っている間はリソースを使わない
macOS では、フォルダが変わったときだけ launchd がプロセスを起動し、変換が終われば終了します。Windows では、1 本のスレッドが I/O 完了ポートで眠るだけです。
変換は使い捨てのプロセスで
必要なときだけ低優先度 (Background QoS / EcoQoS) の子プロセスを起動し、終わったら終了します。使ったメモリはすべて OS に返されます。
安全な置き換え
確認、一時ファイルへの書き込みと fsync、rename、元ファイルが変わっていないかの確認、の順に進めます。日時や Finder タグも引き継ぎます。
設定画面
画質 (最高、高、中、低)、圧縮の強さ、変換するフォルダ、除外するフォルダを設定できます。開いている間だけ動く別プロセスなので、常駐はしません。
OS のネイティブ API
Rust から FSEvents、launchd、ImageIO、AppKit (macOS)、ReadDirectoryChangesW、IOCP、WIC、Win32 (Windows) を直接呼び出します。
公式の JPEG XL 実装
エンコードは libjxl 0.13、確認には jxl-rs を使います (どちらも libjxl プロジェクト、BSD-3-Clause)。

アンインストール

macOS

optiman uninstall --purge
brew uninstall optiman

Windows

「設定」の「アプリ」から「Optiman」をアンインストールするか、次を実行します。

winget uninstall TsubasaTommy.Optiman

変換済みの JPEG XL はそのまま残ります。元に戻したい場合は、アンインストールの前に restore を実行してください。
